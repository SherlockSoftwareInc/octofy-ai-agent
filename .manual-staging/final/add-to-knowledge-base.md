# Add to Knowledge Base

**Add to Knowledge Base** adds a SQL question and its query to the schema library so the built-in agent can reuse it. It is available from the [Schema Library Form](schema-library-form.md): **File > Add Knowledge Base** (the dialog it opens is titled **Add to Knowledge Base**).

## How to use it

1. Open **File > Add Knowledge Base**.
2. In the **Add to Knowledge Base** dialog, enter the **Question** and the **SQL**. If you enter SQL only, click the assistant button to have AI write the question for you — the status line reports **Question generated by AI.** when it succeeds.
3. For built-in agents, the **Build a semantic model from this query** checkbox is available (disabled for Octofy Agent mode and when no vector database directory is set; its tooltip then reads "Semantic models are only available for built-in AI agents."). Check it to also extract a semantic model from the query.
4. Click **Add to KB**.

On open, the dialog searches for entries similar to what you typed and lists them under **Similar existing entries:**, each with a similarity score and a preview of the question (hover a row to see its SQL). If an identical entry already exists, the dialog says so and disables the add button. Both the question and the SQL are required.

## Agent mode behavior

- **Octofy Agent**: the dialog uses the agent's endpoint and API key, checking and writing the remote knowledge base.
- **Built-in Agent**: the dialog uses the data source's library folder (the vector database directory) as the target. Without an embedding provider configured, the similarity check is unavailable and the status line says so.

## The thumbs-up flow

The fastest way to contribute a query is from the AI assistant panel beside the query editor:

1. Submit a request and let the agent produce SQL.
2. When an answer contains SQL, a **thumbs-up** button becomes available (tooltip **Add to knowledge base**); it is hidden while the answer contains no SQL.
3. Clicking it opens the **Add to Knowledge Base** dialog already filled in — the question is taken from the first question of the conversation and the SQL from the query the agent just produced.
4. Review the pair (edit the question if the refinement you asked for changed its meaning), then click **Add to KB**. The thumbs-up button is hidden again once the pair has been added.

The same dialog is reachable from the schema library's **File > Add Knowledge Base** command, where nothing is pre-filled.

## What is saved, and where

- With a **built-in agent** the pair is written to the data source's `vector-index.db` as a few-shot example: the question text is embedded for similarity search and the SQL is stored with it. This is the store the agent's exact-question pre-check and its few-shot retrieval both read.
- With an **Octofy Agent** the pair is posted to the remote agent's few-shot store instead, and the local library is not touched.
- The SQL is stored without the leading comment block the generator may have emitted, so only executable SQL enters the library.

## How it relates to contributions and canonical questions

- A pair added this way is a **curated contribution**: it is treated as a verified example, which is why the SQL is cleaned before saving and why the dialog warns when an identical question is already present.
- The agent's question text is the **canonical question** for that pair — the wording the library recognizes. It is the key for the deterministic exact-question match, so the question you approve here is the phrasing that will be recognised instantly next time.
- Precomputed Q&As are the data-group counterpart of this flow: same question/SQL shape, managed per group in the [Data Groups and Precomputed Q&As](data-groups-and-precomputed-qas.md) review dialog rather than added one at a time.

## Building a semantic model from the query

When the checkbox is checked:

1. The query is extracted into a semantic model — LLM-first, with a SQL-parse fallback — covering measures, dimensions, joins, and tables.
2. The **Edit Semantic Model** dialog opens pre-seeded with the extracted model for review and adjustment. If nothing could be extracted, a message says so and the editor opens with a blank model.
3. Saving the dialog persists the model to the data source's vector database and refreshes the library tree (the model appears under the **semantic-model** node).

See [Semantic Models](semantic-models.md) for more about models.
